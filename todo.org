** Methods
- the expected band for toy CLs needs many toys; add a reuse of s+b toys across quantiles
- adaptive toys target the observed CLs only; an --expected-from-grid style accuracy for the
  expected quantiles is not implemented
- impacts: only the POI r; no --approx robust (robustHesse) and no nuisance groups
- 2D scans run serially (each point starts from its neighbour); --jobs is not used there
- job splitting/merging covers limit and fc; significance --method toys has --jobs only
** Performance
- zmodel toy fits are slow (TF call overhead per NLL evaluation); vectorise over toys
- --jobs: each spawned worker rebuilds the model (a few s with ROOT), so small toy runs gain
  little; refinement points are computed one at a time
** Known small differences from Combine
- Combine (this build, ROOT 6.32) integrates CMSHistErrorPropagator numerically: autoMCStats
  fits are non-smooth and can fail ("integrals don't match"); the mcstats fixture uses a
  workspace patched with RooBinIntegrator (tests/combine_fixtures.py patch_bin_integrator).
  Worth reporting upstream / checking with a newer Combine
- hfmodel: pyhf interpolation for asymmetric lnN inside |theta| < 0.5 and for template
  morphs with mixed scales (declared in notes, documented in docs/backend-hfmodel.md)
- Combine rounds template kappas to %f (about 1e-6 relative)
- TH1 templates: Combine copies them into TH1F (rebinH1: single-precision contents) and its
  CropUnderflows sets every bin < 1e-9 (not only <= 0) to 1e-9; semantics.vertical_morph
  floors only bins <= 0 and keeps double precision (~1e-7 relative).  The RooHistPdf morph
  (semantics.hist_pdf_fractions) already does both; consider the same for templates
- zmodel now reproduces RooFit's default RooIntegrator1D (as Combine) for RooGenericPdf/RooLandauCB,
  computing 15 of RooFit's 20 stages; a pdf that needs more makes nll_main raise (raise the
  stage count or add a dynamic loop if this is ever hit).  Combine's default integrator
  mis-normalises some RooGenericPdfs (3.4% on mumem_75 rmc_ext, 2.5e-4 at kinks)
- zmodel envelopes evaluate every RooMultiPdf component per NLL call (~0.8-1 ms per call on
  mumep_40_env vs ~0.02 ms in roomodel); evaluate only the selected one if it matters
- zmodel expected yields of unbinned channels (Asimov) use bin-centre densities scaled to the
  total, roomodel uses bin integrals: pdf_shape_syst card_unbinned expected yields differ by
  design (NLLs agree to 1e-15)
