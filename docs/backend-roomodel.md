# roomodel (RooFit)

Code: `python/stat_backends/roomodel/`:
- `workspace.py`: IR → RooWorkspace
- `evaluator.py`: C++ bin and event loop, compiled once through cling
- `likelihood.py`
- `export.py`

roomodel is the most general backend. It uses the pdfs from the Combine workspaces as they
are.

## Supported model features
Everything in the IR, including shape systematics on RooAbsPdfs (`syst:pdf-morph`,
`syst:histpdf-morph` and their `shapeN` versions):
- **Data:** counting, binned, unbinned and weighted, also over 2 or 3 observables
  (`obs:multidim`): one RooRealVar per axis, pdfs evaluated at the N-D bin centres times the
  bin volume (binned) or at the N-D events (unbinned) in the C++ loop of `evaluator.py`; N-D
  unbinned toys are generated by RooFit over all axes (`AutoBinned(False)`). Export of N-D
  channels is refused.
- **Shapes:** templates (`shape` and `shapeN`), parametric pdfs with floating parameters,
  `<pdf>_norm` variables and functions, and RooMultiPdf envelopes (`discrete`).
- **Norm terms:** `lnN` (symmetric and asymmetric), `lnU`, `gmN`, `rateParam` (plain and
  formula).
- **Constraints:** every constraint type.

Workspaces with Combine classes (RooMultiPdf, RooLandauCB, …) need
`PYMODEL_ROOT_LIBS=libHiggsAnalysisCombinedLimit.so` in the Combine environment.

## Implementation
- **Parameters.** Each IR parameter is one RooRealVar, created before the workspace objects
  are imported with RecycleConflictNodes, so the imported pdfs use the IR parameters
  directly. Nodes with the same name but different definitions from different files are
  refused (Combine would silently share them).
- **Yields.** `n_exp_<ch>_<proc>` = rate × r × norm terms. lnN is `exp(θ ln κ)`, asymmetric
  lnN is Combine's `logKappaForX` formula, and gmN is α·n.
- **Templates.** Per-bin RooFormulaVars implement Combine's smooth-step vertical morph (and
  the shapeN log morph), with clipping and renormalisation. The Combine library is not needed
  for this.
- **autoMCStats.** In such channels the template fractions follow CMSHistFunc (floor 1e-9,
  no renormalisation), and each Barlow-Beeston-lite parameter adds RooFormulaVars of the
  yields to the (process, bin) cells it acts on; the C++ loop floors the bin totals at 1e-9
  and uses their sum as the extended term. `export` refuses autoMCStats models (the terms
  are not a RooAbsPdf).
- **Shape systematics on pdfs** (docs/statistics.md). RooHistPdf nominal: per-bin
  RooFormulaVars of FastVerticalInterpHistPdf2's morph (TH1F-rounded unit histograms, density
  crop at 1e-9, renormalisation, no normalisation term); no Combine library needed. Other
  pdfs: the imported nominal/Up/Down pdfs in Combine's own `VerticalInterpPdf` when the
  library is loaded (exact by construction). Without the library `shape` is an equivalent
  `RooRealSumPdf` (coefficients = VerticalInterpPdf's quadratic/linear weights) with
  `setFloor`: identical except where the morph is ≤ 0 (0 instead of Combine's 1e-15 floor, so
  the NLL is infinite if such a bin/event has data; a note says so); `shapeN` on such pdfs
  needs the library and binned data. VerticalInterpPdf ignores integration ranges, so bin
  integrals (unbinned channels' expectations, `--bin-integration integral`) are built from the
  raw component integrals with its analytical-integral formula.
  Validation against text2workspace models of `examples/pdf_shape_syst` (ΔNLL at 18 points
  incl. |x| < q and |x| > 1): card 7e-13, RooHistPdf 4e-13, floating 4e-13, unbinned 1.8e-12;
  limits/fits/grids in the fixtures `pdf_shape_syst*`.
- **Binned parametric pdfs** are evaluated at the bin centre × width (or as bin integrals with
  `--bin-integration integral`). The extended term uses the full yield, as Combine does.
- **Envelopes.** The penalty is `RooMultiPdf::getCorrection()`, exactly what Combine's
  CachingAddNLL adds; RooFit counts the observable as a parameter there. Parameters of the
  non-selected pdfs are frozen.
- **Speed.** The NLL is summed in C++ from RooFit evaluations, at about 7–17 µs per call on the
  mumep_ana cards.

## Export
`roomodel export INPUT --native-out ws.root` writes a RooWorkspace `w` containing:
- `model_s`, the main pdf × the constraint pdfs;
- the `<p>_Pdf` / `<p>_In` constraint pdfs and global observables;
- `data_obs`;
- `ModelConfig` and `ModelConfig_bonly`;
- the IR as JSON.

## Validation (`tests/backend_roomodel_check.py`)
**Against the numpy oracle:** ≤ 2e-15 relative.

**Against Combine**, as ΔNLL between parameter points on the text2workspace model of the same
card:

| `combine_mumep_40_evt_r0104_env` (both envelope indices) | 4e-11 |
| `combine_total_mumem_75_evt_r0101` | 3e-14 |
| TH1 templates | 5e-7, from Combine rounding the template κ to `%f` |
| `examples/mcstats` (autoMCStats), after removing Combine's numeric-integral artefact (≤ 7e-3, see `docs/statistics.md`) | 4e-6 (TH1F templates) |
